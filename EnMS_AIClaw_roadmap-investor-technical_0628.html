現況

固定對外邊界：底層 runtime 已完成第一版可驗證能力，但 forecast / anomaly / alert 目前仍應表述為已有底層 path、尚未全面正式產品化。
現在

EnClaw 底層已具第一版可驗證能力，最成熟的主線是自然語言查詢、圖表輸出、缺資料治理與第一版 forecast / anomaly / alert 底層 path。

下一步

未來 90 天先把查詢能力正式化，讓 EnMS 問答、查詢、圖表與報表跳轉變成第一個正式功能頁。

12 個月後

目標是讓 query、governance、analysis 形成一條完整主線，並在受控邊界下驗證本地模型與 VFD user-trigger 控制 pilot。

目前已完成的底層能力
  • 自然語言查詢主線，已具 planner、bootstrap、context pack、chart runtime、source provenance。
  • Bootstrap / data governance，可先確認主資料、schema availability、缺資料邊界與可退回答案範圍。
  • Chart runtime / chart guardrail，能把文字回答與圖表輸出維持在同一份分析脈絡。
  • Review / learning / wiki promotion，可把高價值知識持續沉澱成操作模板與場域經驗。
  • 第一版 forecast / anomaly / alert governance path，已能支撐 EnMS AI 核心敘事。
目前規劃中的產品功能
  • AIAssistant 六個分頁已有功能藍圖與資訊架構草案。
  • 查詢類功能最接近先落地，因為最直接連到既有 EnClaw runtime。
  • 預警與治理適合第二波正式化，能快速產生營運與管理層價值。
  • 深度分析與控制延伸則依資料成熟度、經驗庫與 guardrail 逐步收斂。
一句話結論

/AIAssistant 是開發規劃中的產品入口；EnClaw 是把這些規劃逐步正式化的共用底盤。

8 大核心模組

8 大核心模組

六個分頁不是六套散裝功能，而是共用同一套 EnClaw AI operating layer。

投資語言負責說壁壘在哪裡；技術語言負責說它在 runtime 裡究竟做什麼。
系統邊界一句話

AIAssistant 是入口，EnClaw 是共用 AI 底盤，EnMS 提供資料與既有執行介面，GX10 只是可切換的推理來源，VFD control 則是需 guardrail 與人工核准的受控執行路徑。

展開完整 8 大核心模組說明
1. EnMS-specific Runtime 擴充

投資語言：把通用聊天 runtime 轉成可被 EnMS 正式承接的產品底盤，是後續每個能力頁共用的基礎資產。

技術語言：在 chat / session / active-run runtime 中補上 EnMS routing、bootstrap、review 入口、analytics path 與 chart 接線。

2. Context Builder

投資語言：讓同一個問句能穩定落到對的業務語境，是答對率與可擴充性的核心壁壘。

技術語言：負責 intent 判斷、domain routing、schema / relation / query step 組裝，避免模型直接即興拼 SQL。

3. Context Pack

投資語言：把場域規則、知識、操作經驗與資料結構變成可重複利用的資產，而不是只留在人腦裡。

技術語言：整合 rules、wiki、playbook、integration profile、live query steps 與 domain cheat sheet。

4. Review Flow

投資語言：把 AI 產出納入可審核、可修正、可升級流程，才能把試用價值轉成組織資產。

技術語言：承接 learning draft、auto-trigger、human review 與 promotion 邊界，避免錯誤知識直接寫回。

5. 資料治理

投資語言：讓系統在資料不完整時依然可信，是工業導入裡最常被低估、卻最決定成敗的能力。

技術語言：處理 schema availability、join semantics、gap governance、缺資料提示與風險邊界。

6. 分析模組整合

投資語言：EnClaw 不只會聊天，而是把 forecast、anomaly、alert 等分析模組收斂成正式產品能力。

技術語言：整合需量預警、異常偵測、告警治理等引擎，讓回答有規則與統計依據，不只靠模型語感。

7. 圖表輸出

投資語言：把回答與圖表保持一致，才能讓管理層快速採信，也方便 demo、內部驗收與日常使用。

技術語言：提供 chart runtime、report execute path、renderer 契約與 chart guardrail，確保輸出可穩定落地。

8. Wiki Writeback 整合

投資語言：把一次次現場對話、修正與決策沉澱成可擴張的 know-how，是可複製的長期價值來源。

技術語言：將高價值經驗寫回 wiki、playbook、operation template 與 promotion path，形成知識閉環。

VFD 直接控制

VFD control pilot

先從單一高價值設備族群開始，第一階段先在 /AIAssistant 做 AI 建議驅動的控制模擬 Demo，再逐步把老師傅 know-how 沉澱成可治理、可驗證的產品能力。

敘事順序固定是：先做可展示的模擬 Demo，再結合老師傅經驗庫收斂推薦數值，最後才進入半自動控制與全自動控制。
01

Demo 層

第一階段先在 /AIAssistant 上做可展示的控制模擬 Demo，讓 AI 能根據資料提出調頻建議，並模擬半自動控制或全自動控制的執行畫面與流程。

02

資料層

先確保空壓機壓力、負載、耗能、時段與上下游條件可穩定取得，建立可追蹤的調頻依據。

03

經驗層

收集老師傅在不同情境下的 VFD 調頻數值、可調區間與禁區，讓後續推薦更改的數值有現場知識基礎，避免模型即興判斷。

04

知識層

把經驗沉澱成 wiki、playbook、operation template 與 control guardrail，為跨場域複製建立基礎。

05

控制層

透過既有 PLC、protocol adapter 或 control API，在使用者 trigger 後先進入半自動控制，再逐步驗證全自動控制，形成可審核的控制路徑。

控制邊界

第一階段的重點是把 Demo 做到可展示、可回放、可審核；真正的控制值依據仍建立在老師傅經驗數值與 guardrail，而不是直接讓模型自由生成調頻命令。模型先負責分析、建議與模擬，正式執行則先走半自動控制，最後才評估全自動控制。

模型策略

模型策略

先保留穩定主線，再建立可以量化比較的本地替代能力。

驗證指標固定看答對率、SQL 正確率、穩定度、延遲與成本，不把「可本地化」直接等同於「已可取代」。
穩定主線

現況穩定主線仍以雲端主模型為主，優先確保 query、治理與 chart 回答品質穩定可驗收；目前主要配置仍以 gpt-4.1-mini 為核心。

替代路線

GX10 本地模型是平行的成本與自主化路線，會透過 fine-tune、prompt tuning 與 routing eval 逐步驗證可替代比例，不直接宣稱已完成主力替換。

切換能力

目標保留本地 / AI API 可切換能力，讓題庫、穩定度、延遲與成本可以持續 A/B 驗證。

驗證重點

控制類功能更依賴 playbook、guardrail 與 rule。模型負責分析與建議，不單獨承擔控制責任。

3. 六個分頁會接到同一套核心機制

不是六套各自為政的功能，而是同一套 EnClaw AI operating layer 的不同入口。

4. 12 個月 roadmap 有清楚 phase 與完成條件

從 query、治理、分析到 control extension，phase 順序清楚；下一步重點是把 gate 持續量化。

5. 後段可延伸到 user-trigger 的空壓機 VFD 直接控制

後段差異化不只在 AI 問答，而在把老師傅 know-how 產品化、可治理化，並以 user-trigger pilot 驗證控制路徑。
