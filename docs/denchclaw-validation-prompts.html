先看三個驗證重點

1. Route

問題要被送進正確 domain，不要被別的系統關鍵詞搶走。

2. Bootstrap

回答前要先帶 schema / join / source-of-truth 摘要，而不是直接靠模型猜欄位。

3. Data Gaps

如果資料不完整，必須明確點名缺哪張表、哪個欄位、目前還能回答什麼。

Y-CRM 題庫

客戶背景摘要

請幫我整理 Y-CRM 工作區裡 Calleen Hong 目前負責的客戶背景。
  1. 預期 intent：entity_summary
  2. 回答特徵：應先提及 workspace、owner/assignee join 規則，不該亂猜 person/company 欄位。
  3. 若資料缺口：應明講 auto-schema 或 workspaceMember mapping 是否缺失。

商機圖表延伸

把剛剛的 Y-CRM 商機再用圖表展開，按負責業務分布。
  1. 預期 intent：沿用前一輪 entity_summary / sales_report scope。
  2. 回答特徵：先查真實聚合資料，再決定是否畫圖，不應先吐空 chart。
  3. 若資料缺口：應明講 grouped chart data 是否不存在。

缺資料探針

請直接告訴我這個 Y-CRM workspace 如果缺 auto-schema，現在不能安全回答哪些欄位？
  1. 預期：明講 auto-schema 缺失時不能安全確認欄位、owner FK、table-scoped joins。
  2. 回答格式：應分成 已確認、缺少資料、目前可回答。

ERP 題庫

訂單摘要

請用 ERP 資料整理最近 30 天主要客戶的銷售訂單與出貨進度。
  1. 預期 intent：sales_order 或 shipping_status
  2. 回答特徵：應提到 quoted uppercase table、排除 cancelled_at、company/site scope。

庫存健康

請用 ERP 資料看目前可用庫存最高的前 10 個品項，並提醒我安全庫存風險。
  1. 預期 intent：inventory_status
  2. 回答特徵：應區分 available_qty 與 on_hand_qty。
  3. 若資料缺口：若 INVENTORY 0 rows，必須直接明講。

缺資料探針

如果 ERP 的 SO 或 INVENTORY 沒資料，請直接告訴我缺哪張表，現在還能查什麼。
  1. 預期：應明講 SO 或 INVENTORY 是否 0 rows。
  2. 回答格式：應補一句目前還能做 master-data 或 company/site scope 查詢。

EnMS 題庫

需量預警

請用 EnMS 資料分析大溪廠過去 7 天最大需量、契約容量風險，並提供降載建議。
  1. 預期 intent：demand_forecast
  2. 回答特徵：應先 match 大溪廠，再說明 summary-first、contract-capacity semantics。
  3. 若資料缺口：應直接明講 PowerAccounts / DemandAlertHistory 是否 0 rows。

異常根因

請用 EnMS 資料檢查今天功因、THD、connected、quality 是否有異常，並做根因分析。
  1. 預期 intent：anomaly_detection
  2. 回答特徵：應先看 summary layer，再用 mqtt_raw_data 驗證。

缺資料探針

如果 EnMS 缺契約容量或告警歷史，請直接告訴我缺什麼，並先給我還能做的需量分析。
  1. 預期：直接點名 PowerAccounts、DemandAlertHistory、站點 match 狀態。
  2. 回答格式：應分成 已確認、缺少資料、目前可回答、建議下一步。
目前 EnMS 最值得驗的是「不再模糊地說資料限制」，而是能明確說出缺哪張表、哪個欄位語意沒到位， 然後退回仍可驗證的 summary-layer 分析。
